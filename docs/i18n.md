# Languages

wxbrief writes its plain-language output, its interface text and its numbers in English, Spanish, French, German and
Portuguese. This page covers choosing a language, how the catalogs are built and how to add or fix one.

## Choosing a language

- `wxbrief --lang de` starts the interface in German. `wxbrief decode --lang de "METAR ..."` and
  `wxbrief get --lang de KDEN` print German. The flag is accepted before or after the subcommand.
- In the interface press `S` for Settings, move to the Language row and press Enter to step through the languages.
  The whole interface switches at once (footer, labels, toasts, the detail pane) and the choice is saved to
  `[view] lang` in `config.toml`.
- Without the flag, the interface uses the saved language and `decode` and `get` use English. `decode` and `get` never
  read the config file, so their output does not change with a setting made in the interface.
- `--lang` takes a code from `en, es, fr, de, pt`. A regional code such as `pt-BR` or `es_MX` resolves to its language
  (`pt`, `es`). Anything else is refused with the list of codes.

What is not translated: ICAO and IATA codes, raw report groups, runway designators, station names from the AWC
database, flight-category codes (VFR, MVFR, IFR, LIFR, shown beside a translated long name), unit symbols (kt, SM,
hPa, inHg), theme and key names, and Python's own argparse headings (`usage:`, `options:`). Config and AWC error text
stays English.

## Catalog layout

Each language is one TOML file in `wxbrief/i18n/locales/`. `en.toml` is the reference; the other files carry exactly
the same keys.

```toml
[meta]
language = "Deutsch"        # the language's own name, shown in Settings
status = "seeded"           # "seeded" until a native speaker has read it, then "complete"
plural_rule = "one_other"   # one_other (en, es, de) or one_below_two (fr, pt)
decimal = ","               # decimal separator
group = "."                 # thousands separator
clock = "24h"
min_grouping = 5            # optional: fewest integer digits that get a separator (Spanish: 5)
keep_case = true            # optional: nouns keep their capital when a phrase is joined into a sentence (German)
lowercase_starts = ["Aus"]  # with keep_case: first words that are not nouns and are lowered ("Wind aus 240°")

[wind]
calm = "Windstill"
steady = "Aus {direction}° ({compass}) mit {speed}"

[warn.heading]              # a table of plural categories is a plural entry
one = "{n} Warnung"
other = "{n} Warnungen"
```

Keys are dotted and semantic (`wind.steady`, `remark.peak_wind`). Placeholders use `str.format` names and must be the
same set, with the same format specs, as English; a translation may reorder them. `wxbrief/i18n/keys.py` holds one
constant per key (`K.WIND_STEADY`) and is generated; run `python scripts/gen_keys.py` after editing `en.toml`.

Lookup is `pt-BR` then `pt` then `en`, key by key, and so is `[meta]`: a regional catalog without its own `[meta]` uses
the separators, plural rule and name of its base language, and a key missing everywhere comes back as itself so a gap is
visible instead of fatal. `Translator.t(key, **params)` fills a plain entry, `Translator.plural(key, n, **params)`
picks the form for `n`.

### Numbers

`wxbrief/i18n/numbers.py` formats digits from the catalog's `[meta]`: German writes `1013,2 hPa` and `12.000 ft`,
French writes `29,92 inHg` and `12 000 ft` with a narrow no-break space, Spanish groups from five digits (`3000`,
`12.000`). Unit symbols are never touched.

### Plurals

`one_other` picks `one` for exactly 1. `one_below_two` (French, Portuguese) picks `one` for 0 up to but not including
2. A plural table must have every category its rule can return, and always `other`. Add a rule in
`wxbrief/i18n/plurals.py` (`RULES` and `RULE_CATEGORIES`) before a language needs a different one.

### Interface text

Key bindings carry the catalog key as their `id` (`bind("a", "add_station", K.UI_BINDING_ADD_STATION)` in
`wxbrief/ui/bindings.py`). The English text is the default, and when the language changes the app rewrites every
description from the new catalog. Add a binding with `bind()` and a `ui.binding.*` key; do not write English into
`BINDINGS`.

## Adding or fixing a translation

1. Edit `wxbrief/i18n/locales/<lang>.toml`. Keep the keys and placeholders; change only the text.
2. For a new language, copy `en.toml`, translate it, fill `[meta]`, add the code to `LANGUAGES` in
   `wxbrief/i18n/__init__.py`, and add a test row for its plural forms in `tests/test_i18n_locales.py`.
3. Run `python -m pytest tests/test_i18n_locales.py tests/test_app_i18n.py`. The completeness tests fail on a missing
   or extra key, a changed placeholder, a plural table without `other`, a plural form its rule can never pick, a
   multi-line value (other than the help body) and a catalog that is mostly untranslated.
4. Read a decode in the language: `wxbrief decode --lang <lang> "METAR KDEN 131453Z 06007KT 3/4SM BR OVC003 09/08
   A3001 RMK AO2 SLP165 T00890078"`. Nothing should be English.
5. Change `status` to `complete` once a native speaker has read it.

The es, fr, de and pt catalogs are first-pass translations of the English text and are marked
`seeded`. Corrections are welcome as pull requests.
